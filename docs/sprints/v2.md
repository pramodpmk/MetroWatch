# Sprint v2 — Release Summary

## Overview

This sprint focused on two things: making Kochi's Water Metro a first-class part of the app, and giving the entire experience a visual overhaul. Riders can now check Water Metro stations, routes, timings, and fares from a dedicated home tab, alongside the existing metro rail features. Every major screen — home, station list, station picker, plan trip, fare calculator, timing table, timing detail, metro routes, and parking — was redesigned with an updated look, including initial dark-mode support.

Alongside the visible changes, the team corrected a long-standing bug in how train arrival/departure times were calculated, fixed a bug that could prevent location detection on a freshly installed Android app, rebranded the app (new package identity, name, launcher icon, and logo), and refactored the data layer that the timing, fare, and trip-planning features share.

## Highlights

- Added a Water Metro section to the app, with its own home tab, stations, routes, timings, and fares.
- Corrected an error in the train timing calculation that produced inaccurate arrival/departure times for stations away from the line's starting terminus.
- Fixed a bug where location detection could fail to return a result the first time the app was installed on Android.

## New Features

### Water Metro home section
A new "Boat" tab was added to the bottom navigation, giving Water Metro its own home screen with entry points into Water Metro stations, routes, timings, and fares. Previously, Water Metro data existed in the app's database but had no dedicated home entry point.

### Plan Trip station picking from Home
Riders can now start planning a trip by picking "from" and "to" stations directly on the home screen, rather than only through the Plan Trip screen. Selected stations carry through to the trip planning flow.

### Water Metro fares screen
A new screen lists standard Water Metro route fares (e.g. Kakkanad–Vyttila, High Court–Fort Kochi) as quick-reference cards.

## Bug Fixes

### [Fix] Train timing calculation ignored the line's actual origin
Train arrival and departure times were previously calculated as if every train started its journey at the rider's own departure station. This produced incorrect times for any station that isn't the first or last stop on the line. Timings are now calculated from the line's actual terminus, with the correct travel offset applied before showing times for the rider's selected station. This affects both the Timing Table and Plan Trip screens.

### [Fix] Location could fail to resolve on a fresh Android install
On a newly installed copy of the app, requesting the user's location on Android could fail to return a result because there was no previously cached location to fall back on. Location fetching was moved to Google's Fused Location Provider, which more reliably returns a fresh location on first use, with a fallback to last-known location only if that also fails.

### [Fix] A malformed module reference in the build configuration
A project module was referenced with a technically incorrect syntax that happened to still work; this has been corrected for consistency with the rest of the build configuration. No user-facing impact.
